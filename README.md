# Tasker

A calm, local-first focus workspace for developers — built as a native desktop app with Tauri 2, React 19, and TypeScript.

Tasker is designed around one idea: a short list of real tasks, one clear priority, and enough structure to stop re-deciding what to do next. Everything stays on your machine.

## What is included

- **Focus workspace** — a single priority task with a 25-minute focus timer, checklist progress, live task notes, daily progress, and recent activity.
- **Inbox** — quick capture, inline project and estimate triage, and one-click scheduling for today or tomorrow.
- **Upcoming** — a week strip, per-day plans, focus blocks, weekly stats, and direct task completion.
- **Projects** — progress toward a milestone, status filters, project notes, and a health summary.
- **Task details** — inline title/description/notes editing, acceptance criteria, status, project, priority, due date, and estimate controls.
- **Deleting work** — delete a task from the Task details actions, or delete a project from the project rail. Both ask for confirmation; deleting a project keeps its tasks and moves open ones to the Inbox.
- **Planning tools** — a "Plan the day" flow that gives selected tasks sequential time slots without overlaps.
- **Command palette** — search tasks and projects or jump anywhere with `Ctrl/⌘ K`.
- **Light and dark themes** — a calm dark palette that follows the system by default, with a three-way Light / Dark / System switch in the profile menu and in the command palette.
- **Native desktop behavior** — frameless window with custom traffic-light controls, draggable title bar, native notifications when a focus session ends, and a close-time save flush.
- **Local database** — every task, project, note, and activity is stored in a SQLite database on your machine with transactional saves.

## Stack

| Area | Choice |
| --- | --- |
| Desktop shell | Tauri 2 (Rust) |
| UI | React 19 + TypeScript |
| Build | Vite 7 |
| Styling | Custom CSS with design tokens, bundled Inter variable font |
| Persistence | SQLite database (WAL) in the OS app-data directory |

The domain layer is intentionally object-oriented and immutable: `Task`, `Project`, and `Workspace` classes enforce their own invariants, and every mutation returns a new `Workspace`.

## Getting started

```bash
npm install
npm run desktop        # run the native app (Tauri dev)
```

For browser-only UI work:

```bash
npm run dev            # http://localhost:1420
```

In the browser build, the workspace is saved to `localStorage` instead of SQLite.

## Production build

```bash
npm run build          # type-check + build the web assets
npm run desktop:build  # produce installers under src-tauri/target/release/bundle
```

Windows installers (NSIS and MSI) are generated by Tauri. The application icon is generated from `src-tauri/icons/app-icon.svg`.

## Where data lives

The workspace lives in a local SQLite database:

- Windows: `%APPDATA%\com.tasker.focus\tasker.db`
- macOS: `~/Library/Application Support/com.tasker.focus/tasker.db`
- Linux: `~/.local/share/com.tasker.focus/tasker.db`

The exact path for the current machine is shown in the workspace menu in the sidebar.

Saves are debounced and serialized in the UI, then written in one SQLite transaction in the Rust backend. Tables keep tasks, projects, activities, and workspace metadata (profile, preferences, focus, timestamps), with indexed project, status, and schedule columns. The complete domain record is stored alongside each row so fields such as acceptance criteria round-trip untouched. The backend rejects payloads larger than 8 MB and anything that is not a version-1 workspace.

If Tasker finds a legacy `workspace.json` from an earlier build, it imports it once on first launch and renames it to `workspace.json.migrated` as a backup. Otherwise, new installations start with the sample workspace.

To export a copy, open the profile menu in the bottom-left and choose **Export a copy**. Exports are JSON files written to the app-data `exports/` folder. To start over, choose **Reset sample data**, which clears the database and restores the sample workspace.

The appearance choice is a device preference, not workspace content. It is stored in the webview's local storage under `tasker.theme.v1`, so resetting the workspace does not change your theme. The `theme-init.js` script applies it before first paint to avoid a light flash when the app opens in dark mode.

## Keyboard shortcuts

| Shortcut | Action |
| --- | --- |
| `Ctrl/⌘ K` | Open the command palette |
| `Ctrl/⌘ N` | Add a task |
| `Ctrl/⌘ Shift P` | Plan the day |
| `Ctrl/⌘ 1` | Focus workspace |
| `Ctrl/⌘ 2` | Inbox |
| `Ctrl/⌘ 3` | Upcoming |
| `Space` | Start or pause the focus timer (outside inputs) |
| `?` | Show the shortcut list |
| `Esc` | Close a dialog or step back |

## Project structure

```
src/
  app/            route types and helpers
  components/     title bar, sidebar, dialogs, task widgets
  data/           seed workspace
  domain/         immutable models, types, persistence adapters
  hooks/          focus timer
  lib/            date, id, and platform helpers
  state/          workspace, focus timer, theme, and toast providers
  styles/         design tokens and view styles
  views/          Focus, Inbox, Upcoming, Project, Task details
src-tauri/
  src/            Tauri entry point, commands, and SQLite store
  capabilities/   window and notification permissions
  icons/          generated app icons
```

## Tests

```bash
cd src-tauri
cargo test
```

The Rust unit tests cover payload validation, SQLite round-trips, snapshot replacement, reset, and legacy JSON import.

## Notes

- There is no cloud sync, account system, or telemetry. Tasker is deliberately a single-user, single-machine workspace.
- Sample data is generated relative to the current date, so the demo always looks current.
- The browser preview is a development convenience; the desktop build is the intended experience.
